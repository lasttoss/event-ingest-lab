# Measurements

Generated by `make measure`. Each arm starts from an empty table and pushes the same synthetic
events (same seed, same count, same POST size - 200 events per POST, which is what a game client
sends after being offline). The only variable is how the ingest path turns those events into
INSERT statements.

- Machine: 12 cores, 31 GiB RAM, Linux 7.0.0-38-generic x86_64
- ClickHouse: 25.5.11.15
- Vector: 0.59.0

## The question

> ClickHouse cannot take a lot of requests per second - is that true, and does it mean the
> pipeline needs a queue in front of it?

## The answer, in one line

ClickHouse cannot take many INSERT *statements* per second, and that limit is a property of the
writer, not of the database: the same events that fail as 20,000 single-row inserts land as a
handful of large inserts with the same server, the same table and the same hardware.
